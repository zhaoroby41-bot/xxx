# 小红书 Insight AI 洞察层设计

状态：已完成方案讨论，待用户复核设计文档后进入实施计划。

日期：2026-08-08

## 1. 背景

现有 Insight 已具备 Apple 与经销商双视角页面、月度数据构建、Apple 财季口径和基础指标展示，但整体仍偏向报表呈现。新版需要基于每月爬虫数据、历史数据和 FY26 经销商 KPI，由 AI 生成可解释、可追溯、可执行的运营洞察。

旧版 `笔记报告/xhs_report.html` 中的分析内容需要完整纳入新版，包括整体表现、账号生态、爆文归因、用户反馈、行动指南和业务机会验证。旧版的固定数字和结论不能直接复制，所有结果必须按当前选择月份重新计算和生成。

未来产品会根据登录账号在同一个 Insight 页面展示不同内容。当前设计演示阶段继续使用两个独立页面，但数据合同和权限边界按未来的角色隔离方式设计。

## 2. 目标

1. 将页面的首要内容从指标陈列改为 AI 经营判断。
2. 让每条重要洞察都能追溯到当月或历史数据证据。
3. 按经销商和 Apple 两种角色生成不同判断与行动建议。
4. 支持账号、城市、区域和笔记分类的差异化分析。
5. 统一采用 Apple 财年、财季和财月口径。
6. 新增月份后通过同一套脚本刷新，无需修改前端代码。
7. 同时支持真实 AI 调用、已生成结果复用和规则降级。

## 3. 非目标

1. 当前阶段不实现正式登录、服务端鉴权和组织权限管理。
2. 当前阶段不在浏览器端直接调用大模型。
3. AI 不负责计算 KPI、同比、环比、爆文率等关键数字。
4. 不将旧报告中的历史结论作为新月份的固定文案。
5. 不以聊天机器人作为主要交互形态。

## 4. 数据与时间口径

### 4.1 数据来源

- 每月爬虫数据：账号、笔记和互动表现。
- 历史月度数据：2023 至 2026 年的历史基线和季节性参考。
- FY26 KPI：年度及 Q1-Q4 经销商目标和完成情况。
- 笔记分类、账号城市、经销商归属等映射数据。

### 4.2 时间比较

默认判断同时参考：

- 当前财月。
- 上一财月。
- 去年同期（数据存在时）。
- 历史滚动基线。
- 当前 Apple 财季累计进度与目标节奏。

数据不足时必须降低置信度并显示比较范围，不能用不完整月份推导完整季度结论。

## 5. 双视角信息架构

两个页面采用相同的阅读顺序：AI 本月简报、AI 深度诊断、证据与行动。

### 5.1 经销商视角

仅使用当前经销商及其账号的可见数据：

- 自身财季 KPI 节奏和历史表现。
- 账号、城市和分类的供给缺口与效率问题。
- 自身爆文、长尾内容和热点内容模式。
- 用户互动结构和心智信号。
- 不同城市的差异化内容策略。
- 账号修复、内容增投、减量和发布节奏建议。
- 下一财月可执行的内容日历。

页面和生成给模型的证据包都不得包含其他经销商名称、明细、排名或敏感经营数据。

### 5.2 Apple 视角

使用全网及经销商分层数据：

- 全网财季表现和增长归因。
- 经销商 S/A/B/C 分层与账号生态。
- 头部集中度、长尾效率和同质化风险。
- 城市、区域和分类机会地图。
- 全网 Top 内容与跨经销商可复制模式。
- 风险经销商、异常账号和辅导优先级。
- Apple 节点、产品节奏和渠道内容协同。
- 资源配置和经销商运营建议。

## 6. 旧报告内容映射

### 6.1 增长发生在哪里，为什么

承接旧报告的整体矩阵表现：

- 核心指标趋势、季度增长率和内容形式分布。
- 规模增长、互动增长和内容效率的拆分。
- 部分季度、异常月份和统计范围说明。
- 爆文率下降、质量离散和增长可持续性判断。

### 6.2 账号矩阵是否健康

承接矩阵健康和发布行为分析：

- S/A/B/C 分层和供给效率矩阵。
- 高产高效、低产高效、高产低效和待修复账号。
- 发布频率分布、头部集中度与长尾贡献。
- 内容同质化和资源集中风险。

### 6.3 什么内容值得继续做

承接内容监测和爆文归因：

- Top 内容、长尾爆文和短期热点分别分析。
- 爆文概率特征和可复制模式。
- 标题结构、具体数字、信息差、用户视角和互动提问等模式。
- 产品、场景、促销、教程等分类供给缺口。
- 下一财月选题与标题建议。

### 6.4 用户正在表达什么

承接用户反馈和心智分析：

- 点赞、收藏、评论和分享结构。
- 收藏对应决策阶段、评论对应讨论或购买意图等推断。
- 阅读与涨粉分化、活动驱动增长和异常效率信号。
- 从促销账号向产品知识顾问、本地服务入口等心智定位判断。

所有心智判断必须标记为 AI 推断，并给出数据依据和置信度。

### 6.5 下一步怎么做

承接行动指南：

- 提升爆文率、品牌曝光和 SEO 长尾流量。
- 异常账号修复实验。
- 发布时间、频率、视频比例和热点节点建议。
- Apple 发布会、产品更新和促销节点协同。
- 30/60/90 天行动计划和下月复盘指标。

### 6.6 还有哪些增长机会

承接业务机会验证：

- 需求强度、竞争集中度和内容供给不足。
- 换购、本地服务、分期省钱、女性和学生场景等方向重新验证。
- Apple 输出全网资源配置建议。
- 经销商输出适合自身城市和账号能力的机会。

## 7. AI 生成链路

### 7.1 五阶段流程

1. 数据标准化：统一经销商、账号、城市、分类和时间口径。
2. 特征计算：由 Python 生成确定性指标、异常和候选信号。
3. AI 分析：向模型提交角色隔离后的结构化证据包。
4. 输出校验：检查数字、证据引用、权限和行动完整性。
5. 结果发布：保存版本化 JSON，前端只渲染合格结果。

### 7.2 职责边界

脚本负责事实：

- 汇总、同比、环比、历史基线和财季进度。
- 账号效率、分类缺口、城市差异和互动结构。
- 爆文、长尾、热点、异常账号和同质化候选信号。
- 数据完整度和适用范围。

AI 负责思考：

- 解释指标组合意味着什么。
- 对候选原因排序并说明不确定性。
- 提炼可复制的内容和标题模式。
- 生成角色相关的行动建议与实验。
- 将多个数据点组织成经营叙事。

### 7.3 证据约束

每条洞察必须包含：

- 唯一 ID 和模块类型。
- 判断、原因和影响。
- 一个或多个 `evidence_ids`。
- 置信度和适用范围。
- 明确区分事实、推断和建议。
- 至少一个包含对象、动作、期限和衡量指标的行动。

校验器拒绝以下输出：

- 引用了证据包中不存在的数字或实体。
- 经销商结果包含其他经销商数据。
- 没有证据引用的强结论。
- 建议缺少责任对象或衡量指标。
- JSON 不符合指定 schema。

### 7.4 混合生成模式

- 配置 API Key 时调用真实模型并生成当月结果。
- 当前演示月份保存一份已通过校验的预生成结果。
- 没有 API Key 时优先使用该月份最近一次合格结果。
- 当月不存在合格结果时使用规则模板生成基础分析。
- 页面显示生成模式、数据月份、生成时间、模型和逻辑版本。

## 8. 输出数据合同

建议的洞察对象：

```json
{
  "id": "category_mix_2026_07_01",
  "module": "content_opportunity",
  "title": "生活方式内容供给不足",
  "judgement": "本月内容过度集中于促销类，限制了自然互动增长。",
  "why": "促销类占比上升，但单位阅读和收藏效率低于历史基线。",
  "impact": "账号难以覆盖尚未进入明确购买阶段的用户。",
  "evidence_ids": ["category_mix_07", "save_efficiency_07"],
  "confidence": "high",
  "scope": {
    "period": "FY26 Q4 / 2026-07",
    "cities": ["上海"],
    "accounts": ["ACCOUNT_ID"]
  },
  "actions": [
    {
      "owner": "上海区域账号",
      "action": "增加通勤、学习和家庭场景内容",
      "deadline": "下一个财月",
      "success_metric": "场景类占比达到25%，收藏率提升15%"
    }
  ]
}
```

Apple 输出按月份保存全网文件，经销商输出按月份和经销商 ID 分文件保存。索引文件仅包含角色可见的文件引用，不通过前端过滤一个含全量敏感数据的大文件。

## 9. 页面与视觉规范

### 9.1 布局

- 参考用户提供的大屏运营看板样例。
- 左侧固定导航，顶部提供角色、财年、财季、财月、区域和经销商筛选。
- 第一屏优先展示 AI 总判断、关键变化和行动优先级。
- 深度分析采用宽窄组合面板，AI 判断与支持证据并排。
- 图表和明细是证据层，可展开查看，不抢占经营结论的视觉优先级。
- 卡片仅用于独立信息单元，不嵌套卡片，不将整段页面做成浮动卡片。

### 9.2 Apple iOS 色彩

- 页面背景：`#F2F2F7`。
- 面板背景：`#FFFFFF`。
- 主操作和核心趋势：`#007AFF`。
- 正向机会：`#34C759`。
- 关注事项：`#FF9500`。
- 风险异常：`#FF3B30`。
- AI 洞察：`#AF52DE`。
- 主文字：`#1C1C1E`。
- 次级文字：`#636366`。
- 分隔线：`#D1D1D6`。

颜色用于语义编码，不使用大面积单色铺陈、装饰性渐变或营销式大标题。面板圆角不超过 8px。

### 9.3 响应式要求

- 桌面大屏保持左侧导航和多列证据布局。
- 窄屏转换为单列模块，筛选区可横向滚动或收纳。
- 文本、按钮、图表标签不得溢出或重叠。
- 固定格式图表和工具栏使用稳定尺寸约束，动态内容不得引发布局跳动。

## 10. 月度刷新

目标命令：

```powershell
python 笔记报告/insight/scripts/build_insight.py --month 2026-08 --ai
```

构建过程：

1. 发现并校验当月数据源。
2. 更新 Apple 财季累计和历史比较。
3. 生成 Apple 与经销商证据包。
4. 调用 AI adapter 并获取严格 JSON。
5. 运行 schema、证据、数字和权限校验。
6. 输出版本化快照和最新月份索引。
7. 生成构建摘要、数据质量警告和降级状态。

新增月份不需要修改 HTML、CSS 或 JavaScript。

## 11. 历史回看与版本

- 每个财月保存独立分析快照，不覆盖历史结果。
- 记录数据版本、特征逻辑版本、提示词版本、模型和生成时间。
- 支持按财年、财季和财月切换。
- 历史数据缺少分类或城市时显示覆盖率并降低置信度。
- 算法升级可重算历史月份，但保留旧版本用于审计。

## 12. 失败与降级状态

- 数据源缺失：阻止发布该月份，并报告缺失文件。
- 数据质量不足：允许有限发布，但标记受影响模块和置信度。
- AI 调用失败：使用最近合格结果或规则降级结果。
- AI 输出不合格：拒绝该输出并记录校验原因。
- 单个经销商失败：不影响其他经销商结果，但 Apple 汇总显示覆盖率。
- 前端加载失败：展示明确错误状态，不显示空白图表。

## 13. 测试与验收

### 13.1 自动测试

- Apple 财季和财月映射。
- 当月、历史基线、同比环比和 KPI 累计。
- 分类缺口、城市差异、账号分层和异常候选识别。
- AI JSON schema 和证据引用校验。
- 数字事实一致性校验。
- 经销商角色隔离和文件范围。
- AI 不可用、结果不合格和数据缺失时的降级路径。
- 历史月份切换和前端模块渲染。

### 13.2 视觉验收

- 桌面与移动端无文字溢出、内容重叠和空白图表。
- 第一屏以 AI 判断为主，核心结论无需先读图表即可理解。
- 语义色在机会、关注、风险和 AI 推断之间保持一致。
- 关键洞察可以展开查看证据和代表性笔记。

### 13.3 内容验收

- 旧报告六大领域全部有对应模块。
- 每条强结论都有数据依据和置信度。
- 每条优先行动都有对象、期限和衡量指标。
- 经销商页面不泄露其他经销商数据。
- Apple 页面支持全网、区域和经销商分层判断。
- 新月份加入后可由同一条命令完整刷新。

## 14. 实施边界

本轮实施应在现有双视角 Insight 基础上增量完成：复用当前数据加载、财季计算和角色文件拆分，新增证据层、AI adapter、输出校验、洞察 JSON 和新版页面模块。正式服务端鉴权留到系统化阶段，但静态演示的数据产物从一开始就遵守最小可见范围。
